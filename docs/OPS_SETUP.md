# StudyNova 運維設定

## 24 小時可用

每日單字與已發布內容是資料庫驅動，不需要使用者完成任務才能查看；首頁、學習中心與挑戰頁會持續讀取當日內容。若要讓網站在沒有使用者操作時也持續接收排程或推播，請在管理介面將網站切換到可持續運行的主機模式，並先完成部署，再建立排程。

## CRON／Heartbeat

StudyNova 的排程回呼端點是 `/api/v1/system/cron`，必須以 `POST` 呼叫並帶上 `x-cron-secret` Header。cron-job.org 可直接選擇 Asia/Taipei 時區；若使用 UTC，台灣時間需減 8 小時。每次呼叫的 `uid` 請使用 cron-job.org 的 `%cjo:unixtime%` 或 `%cjo:uuid4%` 變數，避免系統冪等去重把後續執行誤判成重複。

建立或修改排程前，流程是：先把回呼程式推送並建立 checkpoint，再部署正式網站，確認正式網址可連線後才建立排程。不要在本機開發網址上建立排程，也不要在程式內使用 `setInterval`、`node-cron` 或常駐記憶體計時器；排程要由 cron-job.org 觸發 `/api/v1/system/cron`。

排程回呼必須驗證排程身分、使用平台提供的 task UID 查找資料，並讓工作具備冪等性。平台重試時不得重複發送獎勵、通知或建立資料。

## VAPID 推播金鑰

在安全的管理環境產生一組 VAPID 金鑰：

```bash
npx web-push generate-vapid-keys
```

將結果分別設定為以下環境變數，私鑰只能放在伺服器端，不能放進 `NEXT_PUBLIC_*` 或任何前端 bundle：

```env
VAPID_PUBLIC_KEY=你的公開金鑰
VAPID_PRIVATE_KEY=你的私密金鑰
VAPID_SUBJECT=mailto:你的管理員Email
```

使用者登入後到「個人資料／安全與通知」按下「開啟推播」，瀏覽器允許通知後會建立訂閱。管理員可用系統的測試推播確認設定；若要實際寄送，還要確認正式網站使用 HTTPS、Service Worker 路徑可存取，以及瀏覽器通知權限沒有被封鎖。

## 限定功能跑馬燈

管理員到公告管理建立公告，選擇目標受眾、開始與結束時間，勾選「跑馬燈」即可在有效期間顯示於首頁。若要通知使用者，勾選通知；若已設定 VAPID，也可另外啟用推播。PRO 限定公告應選擇 PRO 受眾並設定期限，避免活動結束後仍顯示。


## 久未登入提醒與推播範例

CRON 任務 `inactive_reminder` 會尋找超過 24 小時未登入的學生，每位使用者每日最多收到一則關懷提醒。文案採用俏皮、可關閉、不恐嚇的語氣，例如「你再不來複習，我就要拿望遠鏡找你啦 🔭」、「今天還沒看到你，來做 10 個單字，讓記憶不要飛走吧！」與「只要 5 分鐘也很棒，先從一題錯題開始吧。」。建議在 cron-job.org 建立每日 18:30 的工作，將 `task` 設為 `inactive_reminder`。

管理員可在「管理 → Ops → 公告」中先使用「推播測試」卡，選擇歡迎回來、久未登入、每週小考或限定獎勵範例，也可以自訂標題、內容與點擊後連結。測試推播只會送給目前登入的管理員；正式公告則可設定全部使用者、Nova Pro、指定使用者、跑馬燈、站內通知與 Web Push。

在「管理 → 使用者管理」選取多位使用者後，可使用批次操作授予或延長 Nova Pro、設定指定功能今日無限、贈送 Nova／XP，或選擇「發送通知／推播」一次送出自訂訊息。每項操作都需要填寫原因並寫入 Audit Log。
