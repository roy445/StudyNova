# StudyNova 統一 Nova 扣點清單

**版本：v1.0**  
**適用範圍：AI 解題中心、Novi AI 助理、OCR、測驗分析、作文批改、匯出與其他需要 AI 或計算資源的功能**

## 一、統一原則

StudyNova 應使用同一套 Nova 計費設定與同一套伺服器端扣點流程。AI 解題中心與 Novi AI 助理不得各自建立獨立價格。兩個入口都應呼叫共用的 AI 解題引擎、共用功能代碼、共用扣點規則與共用 Nova Ledger。

所有價格均應由管理員後台設定。前端顯示的價格只用於提示，不能作為實際扣點依據。真正扣點必須在伺服器端完成，並且需要具備冪等鍵，避免使用者重複點擊造成重複扣款。

> **核心規則：先檢查資格與餘額，再顯示確認視窗；使用者確認後才扣點；只有產生有效結果時才完成計費。**

## 三、圖片與 OCR 的特殊扣點規則

圖片格式錯誤、檔案超過大小限制、解析度過低、圖片過度模糊、沒有偵測到有效內容，以及一次偵測到多題時，預設均不扣 Nova。

AI 解題中心一次只能正式分析一題。若系統偵測到兩題以上、整張考卷或多個獨立問題，流程應在扣點前停止，並顯示：

> 一次只能上傳一題喔！請重新裁切圖片，只保留一題，再上傳給 Novi。

此情境不得建立正式解題 Session，不得產生答案，也不得消耗 AI 解題額度。

| 狀態 | 是否扣點 | 是否建立 Session | 使用者操作 |
|---|---:|---:|---|
| 圖片格式不支援 | 否 | 否 | 重新選擇檔案 |
| 圖片太模糊 | 否 | 否 | 重新拍攝或裁切 |
| 題目數量大於一題 | 否 | 否 | 重新裁切成一題 |
| OCR 完全失敗 | 預設否 | 否 | 重新上傳 |
| OCR 成功但題目分析失敗 | 先扣後退款 | 可建立失敗 Session | 重試或回報 |
| 題目分析成功 | 是 | 是 | 顯示解析結果 |

## 四、AI 解題與 Novi 的收費階段

同一題的對話必須維持在同一個 Context Window 中。使用者問「第二步我看不懂」或「可以再簡單一點嗎」時，系統只能針對目前題目延續解釋，不應重新建立另一題，也不應重新收取初次解題費用。

| 階段 | 內容 | 建議扣點 |
|---|---|---:|
| Level 1 | 概念提示 | 初次解題費用內含 |
| Level 2 | 第一個步驟提示 | 初次解題費用內含 |
| Level 3 | 逐步引導 | 初次解題費用內含 |
| Level 4 | 詳細解題方法 | `solution.detailed` |
| Level 5 | 答案核對 | `solution.verify_answer` |
| Level 6 | 完整答案 | 依管理員設定，預設關閉 |

建議初始設定只開放 Level 1 至 Level 4。Level 5 與 Level 6 必須由管理員控制，並可依科目、年級、活動或使用者身分限制。

## 五、後續追問規則

管理員應在「AI Answer Control」中設定以下項目：

| 管理項目 | 建議初始值 |
|---|---:|
| 每題免費追問次數 | 1 次 |
| 免費追問後每次費用 | 2 Nova |
| 每題最多追問次數 | 8 次 |
| 每日 AI 最大消耗 | 100 Nova |
| 是否允許重新表達 | 是 |
| 是否允許生成類似題 | 是，但另行扣點 |
| 是否允許直接顯示最終答案 | 否 |

如果管理員將免費追問次數設為 0，第一次追問也必須在送出前顯示扣點確認。若管理員將追問設為免費，仍應記錄使用次數與 AI 使用量，但 Nova Ledger 不產生扣款紀錄。

## 六、收費確認視窗

所有可能扣 Nova 的功能，在真正開始工作前都必須顯示確認內容。確認視窗至少包含：

| 顯示項目 | 範例 |
|---|---|
| 功能名稱 | AI 解題 |
| 目前 Nova | 42 Nova |
| 本次消耗 | 10 Nova |
| 完成後餘額 | 32 Nova |
| 失敗處理 | AI 沒有產生有效結果時會自動退款 |
| 確認按鈕 | 確認開始 |
| 取消按鈕 | 取消 |

餘額不足時不得建立 AI 工作。系統應顯示需要的 Nova 數量、目前餘額與取得 Nova 的入口。

## 七、退款與 Ledger 規則

所有扣點都必須使用同一套 Nova Ledger。每一次扣款都要記錄原始交易 ID、使用者、功能代碼、金額、狀態與關聯的 AI 工作 ID。

標準流程如下：

```text
Preflight
→ 顯示扣點確認
→ Charge pending
→ 建立 AI Job
→ AI 成功
→ Charge completed
```

失敗流程如下：

```text
Charge pending
→ AI Job failed
→ Refund
→ Ledger 記錄退款
```

相同的 `idempotencyKey` 只能完成一次扣款。使用者重複點擊、網路重送或瀏覽器重新整理，都不能產生第二筆扣款。

| 交易狀態 | 意義 | 是否計入實際消耗 |
|---|---|---:|
| `pending` | 已預留但尚未完成 | 否 |
| `completed` | 已產生有效結果 | 是 |
| `refunded` | 已退款 | 否 |
| `failed` | 工作失敗且未完成扣款 | 否 |
| `cancelled` | 使用者取消 | 否 |

## 八、匯出功能扣點公式

匯出功能應依實際產出檔案大小與格式計算，而不是只依匯出筆數計算。預覽不扣 Nova。使用者按下生成前，系統必須先顯示預估檔案大小與總扣點。

建議公式如下：

```text
totalCost = formatBaseCost + ceil(estimatedBytes / 1MB) × sizeRate
```

建議初始設定：

| 格式 | 基礎費用 | 每 MB 費用 | 備註 |
|---|---:|---:|---|
| CSV | 1 Nova | 1 Nova | 純文字表格 |
| JSON | 2 Nova | 1 Nova | 保留完整結構 |
| TXT | 1 Nova | 1 Nova | 純文字 |
| Markdown | 2 Nova | 1 Nova | 含標題與格式 |
| PDF | 5 Nova | 2 Nova | 需要排版與轉檔 |
| DOCX | 5 Nova | 2 Nova | 需要文件格式化 |
| XLSX | 5 Nova | 2 Nova | 需要試算表格式化 |
| ZIP | 3 Nova | 1 Nova | 多個檔案壓縮 |

實際檔案產生失敗時必須退款。檔案大小應以伺服器實際產出的檔案大小重新核算；若實際費用高於預估值，不得在未重新確認的情況下追加扣點，應採用預估上限或重新顯示確認視窗。

## 九、免費額度與 PRO 規則

Nova 扣點與使用額度是兩個不同概念。扣點代表一次功能消耗的虛擬貨幣，額度代表帳號在每日或每月可使用的次數。兩者都必須由後端檢查。

| 功能類型 | 免費帳號建議 | PRO 帳號建議 |
|---|---|---|
| AI 解題初次分析 | 每日 3 次 | 每日 30 次或管理員設定 |
| Novi 一般回答 | 每日 10 次 | 每日 100 次 |
| AI 追問 | 每題 1 次免費 | 每題 3 次免費 |
| OCR 題目分析 | 每日 3 次 | 每日 30 次 |
| 作文批改 | 每月 3 次 | 每月 30 次 |
| 匯出 | 關閉或僅 CSV | 開放全部格式 |
| 類似題生成 | 每日 1 次 | 每日 10 次 |

即使帳號有免費額度，若該功能設定為 Nova 計費，仍須按照設定扣點。管理員可以將某個功能的 Nova 費用設為 0，代表該功能只受額度限制而不扣點。

## 十、管理員後台設定清單

後台應提供統一的「Nova 與 AI 計費設定」頁面，而不是把價格分散在各個功能頁面。每一筆設定至少包含以下欄位：

| 欄位 | 說明 |
|---|---|
| Feature code | 例如 `solution.initial` |
| 顯示名稱 | 給管理員與使用者看的名稱 |
| Enabled | 是否開放功能 |
| PRO only | 是否限 PRO |
| Nova cost | 固定扣點 |
| Pricing mode | 固定、依檔案大小、依題數、免費 |
| Free quota | 免費帳號額度 |
| PRO quota | PRO 帳號額度 |
| Refund on failure | 失敗是否自動退款 |
| Require confirmation | 是否強制顯示扣點確認 |
| Daily limit | 每日上限 |
| Monthly limit | 每月上限 |
| Max file size | 最大檔案大小 |
| Updated by | 最後修改管理員 |
| Updated at | 最後修改時間 |

管理員修改價格時必須留下設定版本、修改人、修改原因與生效時間。已完成的歷史交易不得因新價格變更而被重新計算。

前端只傳送功能代碼與工作參數。實際 Nova 價格由後端讀取設定，不接受前端傳入的價格。

## 十二、實作優先順序

第一階段應先統一既有功能的計費入口，包括 Novi 回答、AI 建立測驗、英文作文批改、每週小考與匯出。第二階段再加入 AI 解題中心的初次分析、OCR、追問、答案核對與類似題。第三階段才開放科目專用分析、完整答案與進階生成服務。

在所有 AI 解題功能正式收費前，必須先完成四項防護：伺服器端價格查詢、扣點前確認、冪等扣款，以及 AI 失敗退款。未完成這四項前，該功能應設定為 0 Nova 或僅使用額度，避免使用者被錯誤扣點。

## 十三、對使用者的統一說明文案

> StudyNova 會在需要使用 AI 或產生檔案時顯示本次 Nova 消耗。圖片格式錯誤、偵測到多題、OCR 完全失敗，或 AI 沒有產生有效結果時，預設不會扣除 Nova。若工作已扣點但後續發生系統或 AI 服務錯誤，系統會依 Nova Ledger 自動建立退款紀錄。開始前請確認目前餘額、本次消耗與完成後餘額。

## 十四、結論

這份清單將所有 AI、OCR、解題、追問、測驗、作文與匯出功能統一到同一個 Nova 計費模型。建議先採用表格中的初始價格，再由管理員依實際 AI 成本、使用量與免費方案調整。任何價格調整都應只修改後端設定，不應直接修改各個前端頁面。
