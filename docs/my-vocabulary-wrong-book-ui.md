# StudyNova「我的單字」與錯題本 UI 架構說明

## 1. 設計目標

本次介面把「我的單字」與「錯題本」從單純資料清單提升為可持續複習的學習工作區。使用者可以從圖片 OCR、教材分析、挑戰作答與一般測驗累積內容，再依熟悉度、複習進度與錯誤原因安排下一步。介面採用學習中心的既有深色玻璃卡片視覺系統，並以色彩區分狀態，而不是以大量文字堆疊資訊。

> 核心原則：**先看狀態，再做複習；先給答案，再給方法；每次操作都留下可追蹤的學習紀錄。**

## 2. 學習中心資訊架構

| 區域 | 目的 | 主要入口 | 主要行動 |
|---|---|---|---|
| 我的單字 | 收納 OCR、教材與使用者收藏的單字及片語 | 學習中心 → 我的單字 | 搜尋、篩選、朗讀、複習、調整熟悉度、移除 |
| 錯題本 | 收納測驗與挑戰答錯的題目 | 學習中心 → 錯題本 | 依到期日或科目複習、看答案、取得 AI 提示、標記掌握 |
| 圖片 OCR | 產生可保存的單字、片語、題目與教材 | 學習中心 → 圖片 OCR | 品質檢查、智慧分析、加入單字本或題庫 |
| 測驗 | 將我的教材、我的單字與錯題重組成測驗 | 學習中心 → 測驗 | AI 出題、錯題複習卷、手寫與填空測驗 |
| 好友／自我挑戰 | 將題庫內容轉為競賽或個人訓練 | 挑戰 → 挑戰 | 四選一、聽力、手寫、易混淆辨析 |

## 3. 我的單字頁面設計

### 3.1 首屏摘要

頁面上方保留一列三個摘要卡，分別顯示總單字數、需要加強數量與已熟悉數量。數量直接由使用者目前的單字資料計算，避免顯示過期統計。熟悉度低於 40% 的內容以玫瑰色標示，40% 至 79% 使用青色，80% 以上使用綠色。

### 3.2 搜尋與篩選

右上角提供單字或中文釋義搜尋。搜尋會傳送至 `/my-vocabulary?q=`，由後端同時比對英文單字與中文解釋。熟悉度篩選分成「全部」、「需加強」、「複習中」與「已熟悉」，讓使用者能迅速切換學習集合。

### 3.3 單字卡片

每張卡片顯示英文、主要中文、詞性、複習次數、熟悉度徽章與進度條。點擊卡片開啟詳細視窗，而不是直接把所有資料塞在清單中。這種設計保留掃描效率，也讓深度內容有足夠空間呈現。

### 3.4 詳情視窗

詳情視窗包含詞性、熟悉度、音標、中文釋義、例句與中文例句。使用者可以立即朗讀、選擇「我會了」、選擇「加入複習」，或移除內容。複習動作透過 `PATCH /my-vocabulary/:id` 更新熟悉度、複習次數與最後複習時間；移除則使用 `DELETE /my-vocabulary/:id`，並在操作前顯示確認提示。

### 3.5 OCR 串接

OCR 分析結果中的單字與片語仍由使用者逐筆或批次確認後加入。建立前會詢問是否加入「我的教材／我的單字」，避免 AI 分析內容未經確認就污染個人資料。AI 回傳的易混淆字、搭配、字根、聯想與例句保留在 `analysis` 欄位，後續可用於產生辨析題與記憶提示。

## 4. 錯題本頁面設計

### 4.1 進度導向清單

錯題本以題目為主體，每張錯題卡顯示題幹、熟練度、進度條、科目、錯誤次數、複習次數與下次複習日期。篩選器提供「全部」、「待複習」、「已掌握」與科目分類。排序以複習到期時間為優先，使用者不需要自行決定先讀哪一題。

### 4.2 複習流程

點擊「開始複習」會開啟視窗。第一階段只顯示題目與選項，使用者先自行作答或思考；點擊「顯示答案」後才顯示正解、原解析與 AI 記憶法。使用者完成判斷後可選擇答對或答錯，系統依結果調整熟練度與下次複習時間。

### 4.3 AI 提示層級

AI 提示不取代原解析。原解析先呈現，AI 提示則提供更簡單的理解方式、記憶聯想、相似題與下一步建議。這讓使用者先建立解題能力，再使用 AI 作為補救工具。

### 4.4 錯題來源

錯題可以來自一般 AI 測驗、每週小考、好友挑戰、自我挑戰與單字作答。使用者在好友或自我挑戰答錯單字時可以選擇是否加入錯題本，避免每次失誤都自動建立不必要的題目。

## 5. 新增挑戰題型

| 題型 | 使用者介面 | 判分方式 | 適合難度 |
|---|---|---|---|
| 四選一 | 顯示題幹與四個選項 | 比對選項值 | 簡單至普通 |
| 聽力辨識 | 播放英文或中文語音後選答案 | 比對選項值 | 普通至困難 |
| 中翻英手寫 | 顯示中文，輸入英文答案 | 去除前後空白並比對標準答案 | 普通至困難 |
| 易混淆辨析 | 顯示語境或中文，選擇最合適單字 | 比對選項值 | 困難 |

好友挑戰在建立時將題目、方向、選項與題型寫入挑戰 payload，因此兩位使用者看到的是相同內容。自我挑戰則可獨立選擇題型。聽力目前採用瀏覽器語音播放介面，後續可替換為預先生成的語音檔而不改變題目資料結構。

## 6. API 與資料流程

```text
OCR／教材分析
    ↓ 使用者確認
userVocabularies（我的單字）
    ↓ 選擇複習或建立測驗
my-vocabulary API／quizzes API
    ↓ 作答
wordProgress／answers
    ↓ 答錯且使用者確認
questions + wrongQuestions（錯題本）
    ↓ 到期複習
wrong/:id/review + AI tip
```

| API | 用途 |
|---|---|
| `GET /my-vocabulary?q=` | 取得使用者的單字、搜尋與統計來源 |
| `PATCH /my-vocabulary/:id` | 更新熟悉度與複習紀錄 |
| `DELETE /my-vocabulary/:id` | 移除個人單字 |
| `GET /wrong` | 取得錯題、到期數量與解析資料 |
| `POST /wrong/:id/review` | 提交錯題複習結果並調整熟練度 |
| `POST /wrong/:id/ai-tip` | 取得 AI 記憶法與相似題 |
| `POST /words/answer` | 記錄單字挑戰結果，並在確認後加入錯題本 |

## 7. 狀態與錯誤處理

空狀態會提供下一步，而不是只顯示「沒有資料」。我的單字空狀態會引導使用者從 OCR 或教材分析加入；錯題本空狀態則鼓勵開始測驗。API 載入失敗會顯示可重試的錯誤卡。圖片辨識品質不足時，系統會在 OCR 預檢階段顯示「圖片有些內容看不清楚，請拍攝的清楚一點後再分析」，並不會建立低可信度內容。

## 8. 後續建議

下一階段可以將我的單字加入標籤、來源篩選與批次建立測驗。錯題本可以新增「依錯誤原因」分類，例如拼字、詞義、文法、閱讀推論與粗心。聽力題則可以由瀏覽器語音升級為後端產生並保存的音檔，以確保好友挑戰雙方聽到完全相同的聲音。
