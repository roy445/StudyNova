## Current StudyNova facts from repository audit

The project is a Next.js 16 / React 19 application using PostgreSQL + Drizzle, private storage with S3 or PostgreSQL fallback, Redis/BullMQ or PostgreSQL queue fallback, Vercel-compatible deployment, and a REST-like route layer under `src/server/routes`. Existing important tables include `studyMaterials`, `studyMaterialPages`, `questions`, `questionImportJobs`, `quizzes`, `quizAttempts`, `answers`, `wrongQuestions`, `aiConversations`, `aiMessages`, `challenges`, `weeklyExam*`, Nova accounts and transactions, notifications, and platform settings.

Existing AI and privacy foundations are comparatively strong: user ownership checks, private material/OCR/recording/chat handling, session cookies, zod validation, rate limits, Nova transaction idempotency, error codes, storage signing, and an existing Novi context permission model. Existing search is currently a route-backed search modal and should be extended incrementally rather than replaced immediately.

The latest requested UI change is complete: Novi no longer has drag state, pointermove/pointerup handlers, transform-based position state, or a drag cursor. Its dock stays at the fixed responsive bottom-right position and retains open/minimize/chat interactions. This was committed as `605f7ed fix Novi assistant fixed position` and pushed to `main`.

## Cautions

Mem0's README includes managed-platform benchmark claims; those claims should not be treated as independently reproduced OSS performance results. Graphiti's architecture adds an external graph database and LLM/embedding dependencies; it is a design reference rather than an automatic StudyNova dependency. Letta's current repository no longer contains the active server implementation, so the active `letta-code` repository must be reviewed before any recommendation beyond conceptual borrowing.

## Search architecture preliminary decision

For current StudyNova scale and architecture, a staged approach is preferable. Keep PostgreSQL as source of truth and first improve existing `/search` with normalized search documents, PostgreSQL full-text search, `pg_trgm` for typo-tolerant Traditional Chinese/English matching, ownership predicates and optional `pgvector` embeddings. Add a search index only after measuring latency, corpus size and result quality. If a separate service becomes justified, Meilisearch is the simpler license and operational fit; Typesense is technically capable but GPL-3.0; OpenSearch is powerful but operationally much heavier than the current need.

## Adaptive-learning preliminary decision

Do not let an LLM directly decide a hidden learning path. Store explicit mastery signals per concept: FSRS state for recallable items, BKT-style probability for prerequisite skills when enough observations exist, confidence/quality/source provenance, last evidence, and user goal/deadline. A deterministic recommender can rank next activities; Novi can explain the recommendation and accept user corrections. This separates evidence from natural-language coaching.

## Security and authorization references

| Project | Verified design signal | StudyNova decision |

| [Auth.js](https://github.com/nextauthjs/next-auth) | Current repository describes standard-Web-API authentication, CSRF-protected POST routes, restrictive cookies, encrypted JWT defaults, session polling and TypeScript safety. Borrow security checklist items: CSRF, cookie flags, session revocation, revalidation, audit events and provider isolation. |
